Single-process FastAPI application (`main.py`) exposing a `/v1/*` REST surface plus `/healthz`, `/ready`, `/health`. The app is layered as:
- HTTP layer: route handlers in `main.py` with Pydantic request models (`SessionReq`, `ChatRequest`, `EmailAuthReq`, …) and FastAPI `Depends(require_user|require_session|require_admin)` guards.
- Security layer: `auth.py` (PyJWT bearer tokens with `local-ai` audience / `small-cloud-host` issuer), `asgi_guard.SurfGuard` middleware, `rate_limit.client_bucket` per-IP/email windows, and `client_ip.is_direct_loopback` to redact sensitive fields from public responses via `public_view.redact_public_payload`.
- Domain modules: `accounts.py` (register/login/reset/verify), `audit.py` (append/tail events), `store.py` (per-instance SQLite chats), `platform_store.py` (VPS-wide user/feedback/events DB), `instances.py` (multi-instance lifecycle), `moss_runtime.py` + `moss_creds.py` (Moss SDK search/memory), `vault.py` (master-password encryption), `mail_queue.py` (async SMTP outbox), `livekit_tokens.py` + `livekit_probe.py` (voice token issuance).
- External integrations: `ollama_client.py` (model list/pull/stream), `convert.py`, `guardrails.sanitize_user_text`, `config.settings` (pydantic-settings).
- Deployment: Gunicorn + UvicornWorker (`gunicorn.conf.py`), systemd unit `deploy/synap-host.service`, nginx proxy config `deploy/nginx-synap.surf.conf`, purge timer `synap-purge.timer` calling `purge_platform.py`.
Dependency direction is one-way: `main.py` imports domain modules; domain modules never import FastAPI. Boot is wrapped in try/except blocks inside `lifespan` so the marketing VPS stays up even if local instance init fails.
