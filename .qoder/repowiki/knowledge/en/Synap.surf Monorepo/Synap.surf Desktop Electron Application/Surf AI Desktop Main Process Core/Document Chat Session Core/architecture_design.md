Three cooperating modules form the main-process backbone of the desktop app's document and chat features:
- `document-service.ts` exposes a `DocumentApi` factory (`createDocumentApi`) that orchestrates file loading (from disk or the encrypted attachments library), conversion via `document-export`, fill planning/export via `document-fill`, calculator integration, and IPC progress events through `safeSend`/`IPC.documentsEvent`. It also provides `convertChat`, which resolves a conversation's attached files from the DB and writes conversions under `userData/conversions`.
- `chat-route.ts` is a pure-function router: regex-based classifiers (`wantsDeviceControl`, `wantsProjectFiles`, `wantsFreshInfo`) plus `mathJob` / `wordProblem` parse user text into a `TurnPlan` discriminated union (`device | folder | math | web | model`). It also normalizes calculator results back into display text via `phraseMath` and `withWebBanner`.
- `session-store.ts` implements `SessionStore`, an in-memory fallback backed by SQLCipher when available. Every public method branches on `this.db` to either mutate a `Map<string, MemConv>` or run prepared statements against the `conversations`/`messages` schema defined by `SESSION_MIGRATION`. It tracks message versions, sources, and gate metadata, and prunes web-cache entries on deletion.

Dependency direction is one-way: `chat-route.ts` has no dependencies on the other two; `document-service.ts` depends on `db`, `ipc-contract`, `calculator`, and the document I/O helpers; `session-store.ts` depends only on `db` and shared reply utilities. The module does not import Electron renderer code — it communicates outward via IPC contracts and direct `BrowserWindow` event emission.
