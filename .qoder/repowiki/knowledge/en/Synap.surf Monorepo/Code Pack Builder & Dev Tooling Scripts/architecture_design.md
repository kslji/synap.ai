Two distinct concerns live side by side:

- `scripts/code-pack-src/` is a self-contained build pipeline. `catalog.ts` declares the pinned `SourceSpec[]` (Python, Node, MDN, TypeScript, Go, Rust, Docker, etc.) with per-source fetch strategies — raw file lists, GitHub tree walks via the API, or archive downloads — plus a `CleanKind` dispatcher (`html`, `rst`, `java`, `go`, `rust`, `texi`, `adoc`). `build.ts` is the entry point: it resolves signing keys from `CODE_PACK_SIGNING_KEY` / `pack-keys.json` (Ed25519), fetches and cleans each source into `Piece[]`, chunks text via `chunkByHeading` from `apps/desktop/src/main/core/code-pack-chunk.ts`, persists rows through `createCodePackDatabase`/`insertCodePackChunks` into `keyword.sqlite`, writes `NOTICE`, `sources.json`, `manifest.json`, and `manifest.sig`, then ships under `apps/desktop/resources/code-pack/`. Local cards are read from `cards/*.md` frontmatter; external docs are fetched at build time. `sign.ts` handles keygen/signing, `clean.ts` holds format-specific converters, and `keygen.ts`/`clean.ts` are invoked as subcommands.
- Top-level shell/JS scripts (`check.sh`, `check-licences.mjs`, `check-audit.mjs`, `check_python_licences.py`) are CI-only: `check.sh` runs host unittests and harness evals against a running host; `check-licences.mjs` walks `node_modules` and `animation|apps|packages|resources` to reject disallowed licences and catch audio/reference clips that should not be packaged; `check-audit.mjs` shells out to `npm audit` and `pip_audit`, comparing results against `audit-allow.json`.
- `animation/` is a pure data asset: `manifest.json` defines the SVG animation state machine (`idle`, `thinking`, `working`, `happy`, `oops`, `searching`, `reading`, `writing`, `permission`, `typing`, `offline`, `sleepy`, `benchmark`, `wink`, `guiding`, `notification`, `dizzy`) and click handlers consumed by the desktop renderer.

Dependency direction is one-way: scripts depend on `apps/desktop/src/main/core/*` types but nothing in the app depends back on these scripts.
