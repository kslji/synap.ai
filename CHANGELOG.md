# Changelog

Release notes for Surf (Synap.surf). Newest entry first.

## Unreleased

- Versions + HTTPS + CORS (Item 11): added a repo-root **`VERSION`** file (`0.2.0`) as the single source of truth, read by the API through `app/version.py` (which honours an `APP_VERSION` override for the container build, since the image has no repo root) and mirrored by `apps/desktop/package.json`; `/v1/health` and `/v1/version` now report it and the FastAPI app version is no longer the stale `0.1.0`. Rewrote **`deploy/Caddyfile`**: `api.synap.surf` gets automatic HTTPS, automatic HTTP→HTTPS redirect and HSTS plus `X-Content-Type-Options: nosniff` and `Referrer-Policy: no-referrer` (Server header dropped), and a `localhost` block with `tls internal` serves the API over **https://localhost** for local `docker compose up`. Added strict CORS from **`CORS_ORIGINS`** (`app/cors.py`): no origins → no middleware (the desktop app and surf-ide extension are native clients that need none), named origins are served with credentials, and a lone `*` is served **without** credentials (never `*` + credentials). Proxy-header trust is bounded to Caddy via uvicorn's **`FORWARDED_ALLOW_IPS`** (the compose bridge subnet) — the API is only reachable through Caddy, so forwarded headers from elsewhere are ignored. New `deploy/.env.example` vars `APP_VERSION`/`CORS_ORIGINS`/`FORWARDED_ALLOW_IPS` (drift-guarded; `FORWARDED_ALLOW_IPS` exempted as an image-runtime var like `POSTGRES_PASSWORD`). Added `tests/test_version.py` (single-source drift), `tests/test_cors.py` (allow/deny + wildcard-never-with-credentials), and a `/v1/health` version assertion. Gates: API **106 passed**, ruff clean; the compose/https-on-localhost step must be confirmed on a Docker host (Docker isn't available in this environment). surf-ide's extension manifest version is left for the fork commit and must be aligned to `VERSION`.

- Legacy backend removal: deleted **`apps/host`** entirely (the legacy Synap.surf server — Ollama/LM Studio/LiveKit/Moss proxy and server-side conversations) plus its `.env.example`, README, systemd unit, scripts, tests and CI steps; nothing in the release imported it (verified by grep of `apps/desktop`, `surf-ide` and `services/api` before deleting). Cleaned every reference that only served it: `ci.yml` (host job + host-venv licence steps + a stale dev-compose line), `scripts/check.sh`, `build.txt` (now a compose-stack runbook), README layout, the harness (`gate.py` go/no-go main + `smoke.py`/`http_client.py`/`test_convert.py`/`test_guardrails.py`/`test_moss.py`/`retrieval_cases.json` deleted, `run.sh` reduced to `unit|quick|full`, `test_local_first.py` host-legacy ghosts), and `otp_policy`/`ai-orchestrator` comments (orchestrator **parked, not deleted**). In `services/api` the gateway no longer stores chat server-side (product rule: history lives on the device): removed `chat_messages` DDL and `save_chat_message`/`get_user_chat_history` from both stores, rewrote `prepare_messages` to a single `[system, user]` turn, and dropped `GATEWAY_HISTORY_TOKENS`; migration **`0006_drop_legacy`** drops `chat_messages`, the web-search leftovers (`search_requests`, `search_quota_daily`, `source_suggestions`) and `training_examples` (old migrations left untouched). Replaced the removed host limiter with a Valkey-backed per-user + per-IP entry limiter (`app/rate_limit.py`) returning **429 + `Retry-After`** on the gateway `POST /api/v1/chat` and the auth/OTP routes, with a memory fallback in LITE and new `CHAT_*`/`OTP_*_RATE_PER_MINUTE` env vars (documented + drift-guarded). Added `tests/test_rate_limit.py`; expanded `test_migrations.py` (0006 invariants) and rewrote the `test_gateway.py` history tests for single-turn isolation. Gates: API 95 passed, ruff clean (`apps services harness scripts`), `/v1/health` 200, desktop `typecheck` clean, env drift guard + `harness/run.sh unit` pass; the migration chain loads with a single head `0006_drop_legacy` and renders valid SQL offline (a live `alembic upgrade head` needs the Postgres+pgvector image, which isn't available in this environment).

- Env examples (Item 10): regenerated **`deploy/.env.example`** strictly from variables the code actually reads (verified grep of `os.environ`/`getenv`/`ENV`/`process.env`/compose/pydantic fields) — required-in-production set (`JWT_SECRET`, `DATABASE_URL`, `VALKEY_URL`, `OPENROUTER_API_KEY`, `SURF_ENV`, `MAIL_MODE`/`SMTP_*` — ★ marks the four enforced at boot by `startup_guard.py`), optional auth/routing/gateway/licence/pack sections, and a *pack builder (CI / pack box)* section (`EMBED_*`, `PACK_SIGNING_KEY_*`, `CODE_PACK_SIGNING_KEY*`). Dropped `CHAT_PER_*` (never existed in code), `SEARCH_PER_*` (fed only the dead `app.state.limiter` wiring — deleted with `app/limiter.py` + its tests, since Item 3 removed `/v1/search`), `SURF_PACK_CONTENT_KEY` (zero readers), and all `SEARXNG_*`/`SURF_DEV_OPEN` leftovers. Moved and rewrote the root **`.env.example` → `apps/host/.env.example`** (config.py still loads the repo-root `.env`): every host `Settings` field and `gunicorn.conf.py` var is now documented (added the previously-missing `OLLAMA_BASE`/`COLIBRI_BASE`/`LMSTUDIO_BASE`/`LLAMACPP_BASE`/`LOCAL_LLM`/`NUM_CTX`/`NUM_THREAD`/`JWT_TTL_HOURS`/`TRACK_RATE_PER_MINUTE`/`HEALTH_CACHE_SECONDS`/`TRUST_PROXY_HEADERS`/`MAX_CONVERSATIONS`/`MAX_MESSAGES_PER_CONVERSATION`/`MAX_TRACE_FILES`/`LIVEKIT_ROOM`/`MOSS_INDEX`/`LOCAL_AI_*`/`GUNICORN_*`), no active dev secrets (LiveKit dev key pair blanked per the harness rule). READMEs updated. Added `services/api/tests/test_env_example.py` — a bidirectional drift guard (code reads a var missing from the example → fail; example documents a var no code reads → fail) with scanners for the four read styles plus a tested allowlist of OS/library internals; `harness/evals/test_local_first.py` now checks both new file locations. API suite 86 passed, ruff clean.

- Defaults (IDE extension): `gateway-client.ts` and the `surf.gatewayBaseUrl` setting now default to **`https://api.synap.surf`** instead of `http://localhost:8000`, so a fresh install with no desktop-injected `SURF_GATEWAY_BASE_URL` talks to production, not a dev box. Deleted the dead pair `chat-storage-optimizer.ts` + `db.ts` from `extensions/surf-ai/src` (a self-referential stub — the optimizer only imported the never-implemented `db.prepare()` stub and nothing else, including `extension.ts`, referenced either; the identically-named *live* files `apps/desktop/src/main/core/db.ts` and `docs/code-samples/ts/db.ts` were checked and kept). Added `scripts/ext-gateway-default.test.mjs` (guards that both defaults agree on the prod URL and never localhost), wired into `test:unit`. Extension `npm run compile` clean. Note: the spec's "OAuth redirect defaults" has no target in this codebase — sign-in is email OTP end to end; the only redirect-adjacent defaults are the host's CORS/dev-origin lists, which belong to Item 11.

- Release assets (icons): validated the checked-in installer icons and fixed a stale workaround. `build/icon.png` is 1024×1024, `build/icon.icns` is a full multi-size set (16→512@2x), and `build/icon.ico` is a real 7-frame ICO including the 256×256@32bpp frame electron-builder requires. `electron-builder.cjs` had `win.icon` pointing at the generic `icon.png` with a comment claiming the ICO was only 32px — that was no longer true, so `win.icon` now uses `build/icon.ico` (the purpose-built multi-size asset) and the misleading comment is gone. Added `scripts/release-icons.test.mjs` (pure, no PIL/electron: parses the ICO/ICNS/PNG binaries and reads the config by brace-matched block) that fails if an icon regresses to a too-small asset or the config stops referencing the per-OS files; wired into `test:unit`. The Windows NSIS icon path is otherwise unchanged.

- Tests: the desktop `test:unit` was aborting before a single test ran because the script referenced `scripts/offline-bundle.test.mjs`, which never existed (no code, git history, or subject — the offline bundle is already covered end-to-end by `scripts/offline-pack.test.ts` (zip build/refusals) and `src/main/core/offline-pack.test.ts` (all pure hosting/URL/manifest/disk/NSIS/asar logic)). Removed the dangling reference so the 70-file suite now runs. On the API, `pytest.ini` already set `pythonpath = .`; added a central `tests/conftest.py` that `setdefault`s the baseline (`JWT_SECRET`, `JWT_AUDIENCE`, `SURF_API_LITE`, `MAIL_MODE`) so no test depends on an alphabetically-earlier file setting them — `JWT_SECRET` is read at call time (not import), so conftest runs first and resolves it ordering-independently; verified with the real env stripped. API suite 84 passed, ruff clean. Desktop `test:unit` remaining failures are all pre-existing and unrelated to these edits: the sqlite native-binding SIGSEGV (un-rebuilt `better-sqlite3-multiple-ciphers`) and the in-progress IDE code-agent/ask-auto-mode WIP (which does not import anything touched here).

- Desktop typecheck: the toolkit base already supplies `module: esnext` + `moduleResolution: bundler`, so the only gap was electron-vite's `?modulePath` virtual worker import (`calculator.worker?modulePath`) which the node project resolves via `electron-vite/node` types but the web project (which also type-checks `src/main`) did not — `typecheck:web` failed with two TS2307s. Added an explicit ambient `declare module '*?modulePath'` in `src/main/module-types.d.ts`. `typecheck:node` and `typecheck:web` are both clean, so `npm run typecheck` (and `npm run build`) pass.

- Gateway error mapping: added `services/api/app/gateway/errors.py` so a provider/transport failure surfaces as a short, actionable message instead of an opaque 500 or a leak of the provider's response body. `service.py` now maps upstream statuses (bad/expired key 401/403 → clean 503, provider 402 → 402 credits, 429 → 429 with `Retry-After`, 5xx → 502, timeouts → 504) via `raise ... from None` (raw body never chained), turns the mid-stream catch-all from `{'error': str(exc)}` into a typed `{"error":{"code","message"}}` SSE event with a safe message, and replaced the internal `Insufficient balance: need $…, have $…` copy with the standard credits message. The desktop `gateway-chat.ts` now reads the gateway's `detail` for non-OK responses, handles 401/429, and throws on a mid-stream error event rather than silently ending with a partial answer. Provider keys stay server-side; the client still authenticates with its own JWT. Added `tests/test_gateway_errors.py` (10 checks: unit mapping + service integration incl. a streaming error event that must not leak the provider body). API suite 84 passed, ruff clean, desktop `typecheck:node` clean.

- Production safety: added `app/startup_guard.py` and wired `validate_production_config()` into the API `lifespan`, so a server with `SURF_ENV=production` (the repo's existing prod signal, defaulting to `development`) **refuses to boot** on a missing/placeholder `JWT_SECRET`, a non-`smtp` `MAIL_MODE`, or a missing `OPENROUTER_API_KEY` (the Online gateway master key, previously a silent `""` fallback; a gateway-less deployment opts out with `SURF_GATEWAY_OPTIONAL=1`). Removed dev fallbacks that leaked secrets: `dev_code` (OTP) and `dev_key` (licence key) are now hard-suppressed in production regardless of `MAIL_MODE`, not just when console mail is off. Deleted the dead `FETCH_ALLOW_HOSTS` (its SSRF guard was removed with web search) and added `SURF_ENV`/`OPENROUTER_API_KEY` to `deploy/.env(.example)`. Dev/LITE and all tests are unaffected. Added `tests/test_startup_guard.py` (10 checks incl. a real `lifespan` boot that raises before serving); API suite 74 passed, ruff clean.
