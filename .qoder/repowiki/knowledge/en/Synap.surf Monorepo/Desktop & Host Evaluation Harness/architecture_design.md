Two parallel evaluation paths converge on `harness/run.sh`:
- `host` mode (default) executes a chain of pytest-style modules under `evals/` (`test_guardrails.py`, `test_moss.py`, `test_reply_repair.py`, `test_local_first.py`, `test_convert.py`, `test_eval_gate.py`, `test_screenshot.py`) plus `evals/gate.py` which probes `127.0.0.1:18765` for health, zero-knowledge platform bytes, on-device Moss, and loopback-only local LLM, writing `evals/last-report.json`.
- `quick` / `full` modes invoke `core/run_eval.py`, which spawns the Electron app via `npm run eval:electron -w @surf/desktop` with `SURF_EVAL_*` env vars, then scores transcripts through scorer modules in `core/` (`code_split.py`, `documents.py`, `no_fabrication.py`, `step11.py`, `scorers.py`).
- Test data is declarative JSONL/YAML under `suites/shared/cases.jsonl`, `suites/shared/thresholds.yaml`, `suites/niches/marine/`, plus HuggingFace dataset records resolved by `core/datasets.py`; fixtures are materialized into a per-run work dir.
- Scoring output is aggregated by `core/report.py::suite_rows` + `apply_thresholds`, diffed against `baselines/{mode}.json` via `evals/gate.py::compare_eval`, and persisted as `reports/latest.json` plus markdown.
- Dependency direction: `run.sh` → `evals/*` (host checks) or `core/run_eval.py` → `core/*` scorers + `evals/gate.py` comparator; `core` never imports from `evals` except the one-shot import of `gate.compare_eval`.
