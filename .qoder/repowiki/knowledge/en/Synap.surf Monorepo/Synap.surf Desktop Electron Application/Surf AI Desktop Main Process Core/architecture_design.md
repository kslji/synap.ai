The top-level `index.ts` is the Electron main-process bootstrap: it configures `userData`, installs logging/process guards, then branches on env flags (`SMOKE`, `SELFTEST`, `EVAL`) or boots the normal flow by calling `createServices()` from `core/app-services.ts`, which constructs and owns every child subsystem (code-search indexer, file indexer, search connectors, vision pipeline, model lifecycle, document session, live metrics). Cross-child wiring happens through three shared contracts rather than direct imports:
- `core/ipc-contract.ts` re-exports the typed IPC surface from `shared/ipc-contract.js`; all children register handlers via `registerIpc(win, services)` in `main-window.ts`.
- `core/db.ts` (`openUserDb`) opens a single encrypted SQLite database with FTS5 + sqlite-vec extensions; both `code_search_indexer` and `files_indexer` share this schema pattern for hybrid keyword/vector retrieval.
- `core/sidecar-manager.ts` + `core/llama-client.ts` provide the native llama-server process and HTTP client that `model_lifecycle`, `vision`, and the embedding layer all consume.
Children are isolated by feature directory under `core/` and communicate only through these shared primitives plus the IPC channel; there is no cross-import between sibling feature folders.
