Flat registry layout: one subdirectory per agent persona (assistant, code, construction, general, marine, pilot), each containing a single `agent.json` manifest. The schema is uniform across agents — fields include `name`, `tagline`, `description`, `icon` (string token like mail/code/helmet/spark/anchor/plane), `accent` color, `status` (`available` or `coming soon`), `order` (integer for UI ordering), and optional `notes`. There is no runtime code in this module; it is pure data consumed by the frontend to render the agent picker. Domain-specific content lives alongside manifests where applicable (e.g. `agents/code/blog/qwen35-vs-gemma4.md`). Niche domain agents (construction, marine, pilot) share an identical description template referencing a future signed knowledge pack, distinguishing them from the two core available agents (general, code).
