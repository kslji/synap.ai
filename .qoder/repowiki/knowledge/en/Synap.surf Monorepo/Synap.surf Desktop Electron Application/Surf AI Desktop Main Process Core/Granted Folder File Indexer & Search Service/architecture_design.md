Layered around a single `service.ts` factory (`createFileSearch`) that exposes the `FileSearchService` interface to the rest of the main process. Internal layers (dependency direction is inward):
- `store.ts` — persistence layer using `better-sqlite3-multiple-ciphers`, defining the `grants/files/chunks/chunk_vec/chunks_fts/embed_stage/meta` schema, FTS5 triggers, and the `vec0` vector index; all DB access goes through pure functions taking a `FileDb`.
- `indexer.ts` — incremental directory scanner (`listIndexable`, `indexGrant`) with batch/gap pacing, mtime-based skip, pause/resume, and debounced `fs.watch` wrapper (`createWatcher`).
- `permissions.ts` — grant policy: classifies natural-language asks into `FileAsk`, resolves named targets (`~Documents`, Windows drive, folder phrases), enforces exclusion rules, and produces an `AccessPlan` (`search`/`ask`/`refuse`).
- `search-adapters.ts` — pluggable filename search backends: macOS Spotlight (`mdfind`), Windows Search via PowerShell + OLE DB `SystemIndex`, and a recursive walker fallback; every hit is re-filtered against grants.
- Supporting modules: `extract.ts` (file-type extraction), `paths.ts` (cross-platform path normalization), `exclusions.ts`, `limits.ts` (maxFiles/extensions persisted in meta), `os-access.ts` (platform denial classification), `answer.ts` / `suggestions.ts` (response composition).

Embedding strategy is dual-path: new or upgraded grants use EmbeddingGemma vectors; legacy grants keep `hash` embeddings and are background-upgraded via `upgradeHashGrants` → `reembedGrant` → staged commit in one transaction so the two vector spaces never mix. The service serializes all mutations through a Promise-chain queue (`enqueue`) and keeps OS watchers per grant in a `Map` keyed by grant id.
