Two independent CLI entry points share a common pack format but target different consumers:
- `build_pack.py` ingests `.txt`/`.md` files from a source directory, runs each through `app.injection.filter_paragraphs`, calls an external llama-server embedding endpoint (`EMBED_URL`), and writes a full `pack.sqlite` (with `documents`, `chunks`, FTS5 index, and `sqlite_vec` cosine-indexed embeddings) plus a signed `manifest.json`.
- `build_delta.py` parses sitemap/RSS/arxiv/HuggingFace feeds via `xml.etree.ElementTree`, builds a minimal delta SQLite (`delta_meta`, `documents`, `chunks`, `embeddings` as raw float blobs), encrypts it with NaCl `SecretBox` (`PACK_CONTENT_KEY_HEX`), and emits `delta.sqlite.enc` alongside the signed manifest.

Both scripts prepend `services/api` and `harness` to `sys.path` at import time to reach `core.pack_gate.assert_can_sign`, which gates niche signing. The shared `SPEC` dict fixes the embedding model to `embeddinggemma-2-text@256` (native 768-d truncated to 256-d, mean pooling, normalized). `build_delta.py` exposes a `--fixture-embed` mode for deterministic tests that bypasses the remote embedding server. Output is always a surf-pack directory containing `manifest.json`, `manifest.sig`, and either `pack.sqlite` or `delta.sqlite.enc`.
