Layered around a single `CompletionService` (service.ts) that orchestrates the pipeline: debounce per session → cache lookup → snippet selection → FIM probe → prompt assembly → model call → post-processing. The service is host-agnostic via the `CompletionHost` interface; `runtime.ts` wires it to the real world by implementing that interface over `llama-complete.ts` (HTTP `/completion` + `/tokenize`), `http-api.ts` (loopback server exposing the same endpoint), `editor-files.ts`, `policy.ts`, and the external `CodeIndex`. Sub-modules are pure utilities with no cross-dependencies beyond what they expose: `cache.ts` (LRU-style prefix-match cache of completions), `debounce.ts` (`LatestCall` per session using `AbortController` for cancellation), `fim.ts` (FIM marker constants and prompt builder for Qwen2.5/3.x coder models), `snippets.ts` (token-budgeted selection of imported/nearby symbols), `windows.ts` (prefix/suffix windowing around cursor), `post.ts` (tailoring raw completion back into the file), and `ipc-schemas.js` for request validation. Dependency direction is one-way: runtime → service → utilities; nothing in the utility layer imports runtime or service.
