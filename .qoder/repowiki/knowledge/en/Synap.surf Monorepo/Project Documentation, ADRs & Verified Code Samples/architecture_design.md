The module is a flat documentation tree with four sub-trees: `adr/` holds numbered Architectural Decision Records (0001–0003) that capture product-name migration and feature decisions; `code-samples/` is a self-contained TypeScript/Electron reference app (`package.json`, `tsconfig.json`, `electron-builder.yml`) mirroring the real desktop modules for verification, plus Python helpers (`build_pack.py`, `cc_fetch.py`, `publish_r2.py`, etc.) and SQL fixtures (`local_user_db.sql`, `production_postgres.sql`, `pack_manifest.schema.json`); `diagrams/` stores Excalidraw sources alongside exported PNGs for system, HLD, LLD, database-model, niche-agent, and seven-day-plan visuals; `verification/` contains JSON fixtures consumed by the harness. Top-level Markdown files (`ARCHITECTURE-FULL.md`, `ARCHITECTURE-SHORT.md`, `HLD-LLD.md`, `IMPLEMENTATION.md`, `RELEASE.md`, `STEP-*.md`, `DOCUMENTS.md`, `HARNESS.md`, `CURSOR_PROMPT.md`, `AGENTS.md`, `code-pack-eval.md`) form the human-readable spec, while `docs/code-samples/README.md` explicitly states these samples are the frozen verified record from the architecture pack and must not be renamed to match the current app.
