Three sibling modules form the model lifecycle pipeline inside `apps/desktop/src/main/core/`:
- `model-registry.ts` defines the schema (via Zod) for the remote `surf-models/1` registry — `ModelEntry`, `ModelRegistry`, `ALLOWED_LICENSES` — and exposes selection helpers (`pick`, `defaultForAgent`, `smallerChatModel`) that filter by role/tier/agent and pick the largest fitting model.
- `model-download.ts` implements resumable, atomic downloads to `<dest>.part` followed by rename, with pre-check of free disk space via `statfs`, streaming SHA-256 hashing through a `Transform` meter, and a pluggable `fetchImpl` so Electron's `net.fetch` can be injected. Errors are typed via the `DownloadError` class with discriminant `code` (`disk|checksum|network|http|size`).
- `model-eval.ts` is a pure-function evaluation harness over `step11-questions.js`: it selects subset/full question sets, builds prompts per domain (`coding|splitting|run-fix|finance|no-fabrication`), parses single-label replies, summarizes accuracy/no-fabrication/token-rate metrics, and enforces release gates against thresholds.
Dependency direction is one-way: callers in the main process import these three files; they do not depend on each other directly (download does not use registry types, eval does not call download). The only cross-file link is `model-eval.ts` importing `evalQuestions` from `./step11-questions.js`.
